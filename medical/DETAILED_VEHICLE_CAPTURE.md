# 15개 노선 차량 유형·위치 자동 관측

## 조사 대상
`medical/results/v4_implementation_gates.csv`의 저상버스 교체 후보 15개 노선(343, 662, 1124, 1213, 1222, 3212, 3319, 3323, 3413, 5413, 5611, 6620, 6629, 6648, 7211)을 조사한다. 노선명별 공식 노선 ID는 `medical/raw/vehicle_candidate_route_ids.json`에 기록했으며 2026-10-17 노선정보 CSV에 근거한다. 실제 API 응답에서 유효한 ID인지는 실수집으로 재검증한다.

## 자동 시각 (한국시간)
- 평일: 08:00~08:25, 10:00~10:25, 14:00~14:25, 17:00~17:25, 각 시간대 5분 간격 6회
- 주말: 10:00~10:25, 16:00~16:25, 각 시간대 5분 간격 6회

각 실행에서 15개 노선을 각각 한 번 조회하므로 평일 최대 360회, 주말 최대 180회 요청한다. 이는 사용자가 확인한 '상세기능별 일일 트래픽 1,000' 이내의 계획 요청량이다. GitHub Actions 스케줄은 정시가 보장되지 않으며 지연·누락될 수 있다. 수집기 응답 요청은 15초 타임아웃을 적용하고 15개 요청을 순차 처리한다. 동시 요청을 보내지 않는다.

## 보관·추적
- 노선별 전체 관측 차량 유형과 오류: `observations/vehicle_timeseries.csv`, `observations/vehicle/aggregate-*.json` (공개 가능한 집계)
- 정류소 구간별 저상/일반 차량 관측 수: `observations/vehicle_section_timeseries.csv` (공개 가능한 집계)
- 연속 관측에서 같은 가명차량의 구간순번 증가·감소·정체: `observations/vehicle_transitions.csv` (공개 가능한 집계; 같은 날짜 25분 이내에서만 비교)
- 차량별 일자·관측 시각, 가명차량키, 구간순번, 위치 좌표, 운행·정류소 플래그 등: `observations/vehicle_encrypted/vehicle-*.enc` (AES-256-GCM으로 암호화한 상세 기록)
- 위치 기록은 작업 중에는 임시 경로의 JSONL이며 원시 차량 ID·번호판을 남기지 않는다. 가명차량키는 같은 날짜·노선의 반복 조회에서 유지되며 다음 날짜에는 바뀐다.
- 암호화 키는 기존 GitHub Secret `SEOUL_BUS_API_KEY`에서 영역 분리된 HMAC으로 파생된다. 별도 키 입력은 필요 없지만 **서비스키를 교체하면 이전 암호화 파일을 복호화할 수 없다.** 키 교체 전에 기존 상세 자료를 별도로 안전하게 백업해야 한다.
- 공개 Git 저장소에는 암호문과 집계만 커밋하고, 차량별 원문·가명키는 올리지 않는다. 암호화 전 상세 자료는 GitHub 작업자 임시 디렉터리에만 생성한다. 실행별 Actions 아티팩트도 상세 정보는 암호문만 담는다.

## 해석 제한
- 시간 간격과 차량 위치 관측만으로 실제 정류소 도착, 휠체어 탑승 여부, 승객 대기시간을 증명하지 않는다.
- `section_seq` 전후 변화는 관측 시점 사이 구간 순번 변화일 뿐 실제 이동 거리나 속도 측정이 아니다. 회차·노선 순서 변경·관측 누락에 유의한다.
- 한 시점의 관측 수는 고유 보유 대수가 아니며 여러 시점의 관측 차량 수를 합산해 실제 운행 대수라고 하면 안 된다.
- 매 실행마다 `successful_requests`와 오류 코드를 확인하며 실패/빈 응답은 미운행의 증거가 아니다.

수집 정지는 GitHub Actions 워크플로 비활성화 또는 `.github/workflows/vehicle-capture.yml`에서 `schedule` 삭제로 수행한다.
